
# 从 TypeScript 结构类型到 ArkTS 显式继承的改造实录

TS 的结构类型系统"长得像就行"，这在快速原型期很爽，但在 ArkTS 里行不通 —— ArkTS 要求**显式的类型关系**。本脚手架的数据模型经历了两轮改造。

## 第一轮：字面量满天飞

早期图快，页面间传参直接用字面量：

```typescript
router.pushUrl({
  url: 'pages/TagDetailPage',
  params: { tag: 'ArkTS', count: 3, from: 'list' }   // 无类型字面量
});
```

接收端用 `router.getParams()` 拿到 `Object` 后逐字段 `as` 断言取值。字段改名时编译器**毫无感知**，只能靠运行期白屏发现。这正是参考项目 `checkTags.js` 存在的原因 —— Web 项目用脚本做事后校验，而我们可以在编译期就杜绝。

## 第二轮：显式接口模型

### 1. 定义数据接口层（model/）

```typescript
export interface ArticleMeta {
  slug: string;
  title: string;
  description: string;
  category: string;
  tags: string[];
  wordCount: number;
  createTime: string;
  updateTime: string;
  order: number;
}

export interface ArticleIndex {
  meta: IndexMeta;
  files: ArticleMeta[];
}

export interface TaxonomyItem {
  name: string;
  count: number;
}

export interface Taxonomy {
  generatedAt: string;
  tags: TaxonomyItem[];
  categories: TaxonomyItem[];
}
```

### 2. 页面参数显式化

每个详情页声明自己的参数接口，并在 `aboutToAppear` 中做**字段级校验**：

```typescript
interface TagParam { tag: string; }

aboutToAppear(): void {
  const p = router.getParams() as TagParam;
  this.tag = p.tag ?? '';
  if (this.tag === '') {
    router.back();   // 参数缺失直接退回，避免白屏
  }
}
```

### 3. 仓库接口化（data/）

`DataRepository` 对页面只暴露类型化方法：`getAllArticles(): ArticleMeta[]`、
`getArticlesByTag(tag: string): ArticleMeta[]`……页面永远拿不到裸 `Object`。

## 结构类型残留的典型报错

| 报错 | 原因 | 改法 |
|---|---|---|
| `arkts-no-untyped-obj-literals` | 字面量无类型上下文 | 变量/参数加 interface 注解 |
| `arkts-no-structural-typing` | 两个形状相同的 interface 互相赋值 | 显式继承：`interface A extends B` |
| 运行期 undefined | `as` 断言掩盖字段缺失 | aboutToAppear 字段校验 + 默认值 |

## 收益

改造后，`index.json` 的字段一旦在构建脚本里改名，**应用侧所有消费点全部编译报错**，重命名从"全局搜索碰运气"变成"跟随编译器"。这正是把参考项目里 `check.json` / `seocheck.js` 这类**事后校验**升级为**事前约束**的过程。
