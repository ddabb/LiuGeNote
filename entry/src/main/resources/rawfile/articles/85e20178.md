
# ArkTS 与 TypeScript 核心差异清单：从 TS 迁移前必读

把 TS 代码直接拷进 `.ets` 文件，十有八九编不过。ArkTS 不是「TS + 装饰器」，而是**为性能收紧的 TS 子集**：砍掉运行时类型不确定性，换取更优的编译优化与更小的包体。

## 差异总表

| # | TypeScript | ArkTS | 原因 |
|---|---|---|---|
| 1 | `any` / `unknown` | 禁用 | 破坏类型推断 |
| 2 | 结构化类型（形状兼容即可） | 名义化：必须显式继承/实现 | 降低运行期检查成本 |
| 3 | 对象字面量作类型 | 禁用，抽 interface | 类型必须在编译期确定 |
| 4 | `as` 任意断言 | 仅限 JSON.parse 接收等窄场景 | 防「断言掩盖错误」 |
| 5 | 索引签名 `obj[key]` | 禁用，用 `Record<K, V>` | 动态访问不可静态优化 |
| 6 | 解构赋值/展开 | 禁用 | 字节码优化困难 |
| 7 | 函数表达式/匿名函数 | 禁用，用箭头函数或具名函数 | 同上 |
| 8 | `var` | 禁用，用 `let`/`const` | 作用域陷阱 |
| 9 | 高阶函数随意嵌套 | 受限：UI 回调需显式类型 | 可读性与优化 |
| 10 | 工具类型 `ReturnType` 等 | 仅 `Partial`/`Required`/`Readonly`（类/接口） | 其余依赖结构推断 |

## 三条最常踩的差异详解

### 结构化类型 → 名义化

```typescript
// TS：形状一样就能赋值
interface A { x: number }
interface B { x: number }
const b: B = { x: 1 };
const a: A = b;              // ✅ TS OK

// ArkTS：形状相同不算数，必须有显式继承关系
interface A { x: number }
interface B extends A { }    // 必须声明 extends
const a: A = { x: 1 } as B;  // ❌ 仍不行：字面量直接标 A
```

结论：**一个模型一份 interface，跨模型复用走继承**，别指望「长得像就行」。

### 索引签名 → Record

```typescript
// ❌ ArkTS 禁止索引签名与动态属性访问
const map: { [key: string]: number } = {};
map['a'] = 1;
console.info(`${map['a']}`);

// ✅ Record + 显式键
const map: Record<string, number> = { 'a': 1 };
const key: string = 'a';
map[key] = 2;                 // Record 允许动态键访问
```

注意 `Record` 只解决「容器」问题；**普通对象上 `obj[dynamicKey]` 依旧报错**。

### 解构与展开 → 显式赋值

```typescript
// ❌
const { title, slug } = article;
const merged = { ...defaults, ...overrides };

// ✅
const title: string = article.title;
const slug: string = article.slug;
const merged: Options = {
  fontSize: overrides.fontSize ?? defaults.fontSize,
  theme: overrides.theme ?? defaults.theme,
};
```

## 迁移建议

1. 先跑 `arkts_check` 看清单级错误，按规则分类批量改，别逐个试错；
2. 数据模型全部抽成显式 interface/class，这一步做完能消灭一半报错；
3. 回调全部箭头函数化，参数显式标类型；
4. 剩下的 `as any`、`obj[key]` 逐个按本表第 4、5 条改写。

## 一句话总结

ArkTS 的哲学是**「编译期能确定的，绝不留到运行期」**。迁移前把这张表过一遍，改起来就有章法。
