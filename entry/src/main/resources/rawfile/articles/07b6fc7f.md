
# V1 与 V2 状态管理怎么选：@State、@Local 与 @Observed 全家福

ArkUI 的状态管理有两代体系：V1（`@Component`）与 V2（`@ComponentV2`）。两代**观察模型不兼容**，同一个 struct 里混用是最高频的编译报错来源。

## 两代装饰器对照

| 职责 | V1（@Component） | V2（@ComponentV2） |
|---|---|---|
| 组件内部状态 | `@State` | `@Local` |
| 父传子单向 | `@Prop` | `@Param`（默认可变，`@Once` 只同步一次） |
| 父子双向 | `@Link` | `@Param` + `@Event`（`!!` 双绑） |
| 跨层级共享 | `@Provide` / `@Consume` | `@Provider` / `@Consumer` |
| 观察嵌套对象 | `@Observed` + `@ObjectLink` | `@ObservedV2` + `@Trace` |
| 派生值 | 手写方法 | `@Computed` |
| 变化监听 | `@Watch` | `@Monitor` |

## 选型的三条硬规则

### 规则一：一个 struct 只能属于一代

```typescript
@Component
struct BadMix {
  @State count: number = 0;   // ✅ V1 合法
  @Local name: string = '';   // ❌ ERROR：@Local 只能用于 @ComponentV2
}
```

报错信息是「decorator can only be used in a 'struct' decorated with @ComponentV2」。整个组件树保持同代，最省心。

### 规则二：V1 状态不能持有 @ObservedV2 实例

`@State` 观察的是**第一层赋值**，嵌套属性变化靠 `@Observed`+`@ObjectLink` 代理。把 `@ObservedV2` 类的实例放进 `@State`，V1 不会为它建立深度观察——UI 永远不刷新，且没有任何警告。

```typescript
@ObservedV2
class Progress {
  @Trace percent: number = 0;
}

@Component
struct Reader {
  @State progress: Progress = new Progress(); // ❌ 静默失效：percent 变化不触发刷新
}
```

正确做法：这个组件要么整体升级 V2 用 `@Local`，要么模型改回 `@Observed` + `@ObjectLink`。

### 规则三：V1 存储容器不放 V2 对象

`AppStorage`、`LocalStorage` 是 V1 的全局观察容器，往里 `setOrCreate` 一个 `@ObservedV2` 实例同样观察不到。V2 对象的全局共享要用 `AppStorageV2` / `PersistenceV2`。

## 什么时候值得迁 V2

- 模型层级深、嵌套属性需要精确观察：`@ObservedV2`+`@Trace` 是**属性级**观察，比 V1 的类级代理更细，刷新范围更小；
- 需要派生值自动更新：`@Computed` 比手写 `@Watch` 回调可靠；
- 只想「父传子、子改回」：`@Param`+`@Event` 语义比 `@Link` 的隐式双向清晰。

反过来，页面结构简单、只有扁平状态时，V1 完全够用，**不必为了新而新**。

## 迁移踩坑记录

1. `@Link` 初始化必须传引用：`Comp({ aLink: this.aState })`，旧的 `$aState` 写法已废弃；
2. V2 双向绑定用 `!!`，与 V1 组件的 `$$`（如 `TextInput.text`）不是一回事；
3. V1 的 `@Component` 里不要写 getter 访问器——转换器会丢弃它们，运行期读到 undefined 直接崩溃，需要暴露值就写成普通方法。

## 一句话总结

**按组件树选代际，按数据深度选模型**：浅状态 V1，深嵌套 V2，两代对象永不互存。
