
# promptAction 与 UIContext：全局弹窗的正确打开方式

「复制成功」toast、「确认清空？」对话框——弹窗看似简单，API 版本一多就容易用错对象，最常见的翻车是**拿着 context 调 UI API**。

## 弹窗 API 的三条路径

### 1. AlertDialog —— 静态调用

```typescript
AlertDialog.show({
  title: '清空错题本',
  message: '错题记录将全部删除，不可恢复。',
  primaryButton: {
    value: '取消',
    action: (): void => {}
  },
  secondaryButton: {
    value: '清空',
    fontColor: '#D9480F',
    action: (): void => { this.doClear(); }
  }
});
```

### 2. promptAction —— 轻提示

```typescript
import { promptAction } from '@kit.ArkUI';

promptAction.showToast({ message: '已复制代码片段', duration: 1500 });
```

### 3. UIContext 实例方法 —— 推荐路径

```typescript
this.getUIContext().getPromptAction().showToast({ message: '已复制' });
this.getUIContext().getPromptAction().openToast('已复制', 1500);
```

## 为什么要走 UIContext

旧的静态调用在**多实例 / UI 未就绪**场景下可能找不到宿主窗口，表现就是「代码跑了，弹窗没出来」。通过组件内 `this.getUIContext()` 拿到 UI 实例再操作，绑定关系明确：

- `this.getUIContext()`：组件内拿 UI 上下文；
- `getContext(this)`：拿 ability 上下文（用于资源、preferences），**它不是 UIContext，调不了弹窗**。

## 两个 context 别再混了

| 对象 | 获取方式 | 用途 |
|---|---|---|
| common.Context | `getContext(this)` | resourceManager、preferences、应用目录 |
| UIContext | `this.getUIContext()` | promptAction、router、animateTo、弹窗 |

工具类（非组件）里要用 UIContext，由调用方把 `UIContext` 实例传进来，别在工具类里硬取。

## 弹窗不弹出的排查清单

1. **静态调用目标窗口丢失**：改走 `getUIContext().getPromptAction()`；
2. **时机太早**：`aboutToAppear` 里弹窗，UI 还没挂载——挪到 `onPageShow` 或用户事件回调里；
3. **被页面遮罩盖住**：自定义遮罩层级高于 toast 宿主层，调整蒙层方案；
4. **多 UI 实例**：入口窗口与子窗口各有一套 UIContext，弹错了窗口自然看不见。

## 体验细节

- toast 文案带结果动词：「已复制」「已保存」，别只写「成功」；
- 破坏性操作（清空、删除）的确认按钮放**右侧**且标警示色，取消在左；
- 高频操作（连点复制）toast 会叠着出，重复触发前先dismiss或允许覆盖即可，不必节流到无反馈。

## 一句话总结

**能力上下文管资源，UI 上下文管弹窗**。`getContext(this)` 与 `this.getUIContext()` 各司其职，弹窗一律走 UIContext 实例。
