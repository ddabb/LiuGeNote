# 中文参数路由跳转：router 传参编码与页面回退链设计

应用的标签、分类几乎全是中文（"ArkTS 严格模式"、"环境与工程配置"）。六 个页面之间的跳转全靠把这些中文名当路由参数传，踩坑记录如下。

## 坑一：中文参数的防御性编码

### 现象

`router.pushUrl` 的 params 是对象序列化传递，正常中文名多数情况下没问题，但**含空格、`#`、`&`、`+` 的名称**在部分设备上会被截断或转义出错。比如标签 "DevEco Studio" 跳到详情页后变成了 "DevEco"。

### 解决：统一编解码约定

跳转侧统一编码，接收侧统一解码，封装成唯一的入口函数：

```typescript
import { router } from '@kit.ArkUI';

export function gotoTagDetail(tag: string): void {
  router.pushUrl({
    url: 'pages/TagDetailPage',
    params: { tag: encodeURIComponent(tag) }
  });
}

// TagDetailPage.ets
aboutToAppear(): void {
  const p = router.getParams() as TagParam;
  this.tag = p.tag ? decodeURIComponent(p.tag) : '';
}
```

规则写进了 `docs/design.md`：**任何字符串路由参数必须 encodeURIComponent**，不允许裸传。

## 坑二：getParams 的空值兜底

用户可以从文章详情页直接跳到另一个标签详情页，也可能从深链直接进入。`router.getParams()` 在直启场景返回 `undefined`，直接 `.tag` 取值会崩溃。

兜底策略（每个详情页一致）：

1. `getParams()` 判空；
2. 字段判空，缺失时赋默认值或 `router.back()`；
3. 页面数据加载失败（查不到该标签）时展示**空态文案**而不是白屏。

## 坑三：回退链失控

早期为了"方便"，详情页里放了"返回首页"按钮，用户点了之后 `router.back()` 回到的却不是首页（回退栈不会说谎）。梳理后确定导航模型：

```
首页 ──► 标签列表 ──► 标签详情 ──► 文章详情
   └──► 分类列表 ──► 分类详情 ──► 文章详情
文章详情 ──► (文内标签/分类) ──► 对应详情页 ──► 新文章详情 …
```

- 全部跳转用 `router.pushUrl`（压栈），返回交给系统返回键与 `router.back()`，**回退顺序天然正确**；
- 移除所有"跳回某页"的快捷按钮，避免破坏栈序；
- 页面栈深度没有硬限制，但长链浏览后提供顶部返回，符合用户预期。

## 坑四：页面未注册导致的静默失败

新增 `TagDetailPage` 后忘记在 `resources/base/profile/main_pages.json` 注册，`router.pushUrl` 报 `1004`（页面不存在）。规范：**每加一个页面，同步三处** —— 页面文件、`main_pages.json`、跳转封装函数。

## 传参速查表

| 跳转 | 参数 | 编码 |
|---|---|---|
| → 文章详情 | `{ slug }` | 是 |
| → 标签详情 | `{ tag }` | 是 |
| → 分类详情 | `{ category }` | 是 |

导航是离线应用的骨架。编码、兜底、栈序三件事做扎实，六个页面就是一张稳定的网。
