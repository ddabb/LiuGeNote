# 离线应用的权限最小化与包体积控制

"离线"不只是不联网的体验，更是一组**工程约束**：零权限声明、零网络请求、可控的包体积。

## 权限最小化

### 检查清单

打开 `entry/src/main/module.json5`，`requestPermissions` 应为空数组：

```json
{
  "module": {
    "requestPermissions": []
  }
}
```

离线内容应用需要的读写都在**应用沙箱与随包资源**内完成：

| 能力 | 是否需要权限 |
|---|---|
| 读 rawfile（随包资源） | 否 |
| router 页面跳转 | 否 |
| 本地缓存（内存/沙箱） | 否 |
| 网络请求 | **不做** |

### 收益

1. 上架审核无需填写权限用途说明；
2. 用户安装时无敏感权限弹窗，转化率友好；
3. 从架构上杜绝"离线应用偷偷联网"的信任问题。

## 包体积控制

### 数据体积实测

脚手架当前内容（10 篇演示文档，约 2.5 万字）：

| 组成 | 体积 |
|---|---|
| `rawfile/articles/*.md`（正文） | ~60 KB |
| `rawfile/index.json` | ~5 KB |
| `rawfile/taxonomy.json` | ~1 KB |
| HAP 基础壳（模板 + 图标） | ~1 MB 级 |

内容数据相对 HAP 壳可忽略不计。这意味着**纯文本内容可以放心堆量**：
一篇 5000 字长文 ≈ 15 KB，一千篇也仅十几 MB。

### 与 Web 静态站对比

参考项目 `vercel-ci` 每篇文章产出独立 HTML（含 Bootstrap CDN 引用与内联样式），
单页体积 30~80 KB；我们存 md 纯文本，单篇 5~15 KB，且**渲染代码只有一份**（应用内解析器），
不是每篇文章复制一份。离线原生化后内容密度显著更优。

### 体积红线与策略

1. **图片是大头**：md 里若引入图片，必须随包放 `rawfile/assets/`。当前演示内容刻意零图片，
   脚手架保持纯文本最轻形态；接入图片时应压缩并设定单图上限（如 200 KB）；
2. **不预置字体**：系统字体满足中文渲染，不自带 ttf（参考项目 fonts 目录 10+ MB，不迁移）；
3. **资源目录卫生**：`resources/base/media/` 只保留模板必要图标，清理未引用资源。

## 离线的边界：什么情况不该用本方案

诚实记录适用边界：

- **内容超大**（数百 MB 音视频）→ 应改用分布式文件或按需下载，不适合全量 rawfile；
- **内容需频繁热更** → rawfile 随包发布，更新走应用升级；需要热更应引入服务端下发方案；
- **强交互内容**（表单、评论）→ 纯静态渲染模型无法承载。

本脚手架定位：**中量级、低频更新、强离线**的阅读型内容 —— 与参考项目"无人自助站"的定位一脉相承。
