# 权限声明与隐私合规：零权限应用的合规设计

「这个应用要通讯录权限干嘛？」——用户 uninstall 的理由，也是审核驳回的理由。权限合规的核心不是「怎么申请」，而是「能不能不申请」。

## 权限体系速览

```json5
// module.json5
"requestPermissions": [
  {
    "name": "ohos.permission.INTERNET",
    "reason": "$string:internet_reason",       // user_grant 必填
    "usedScene": {
      "abilities": ["EntryAbility"],
      "when": "inuse"
    }
  }
]
```

| 类型 | 例子 | 声明后行为 |
|---|---|---|
| system_grant（系统授权） | INTERNET、屏幕常亮 | 装机即生效，无需弹窗 |
| user_grant（用户授权） | 定位、相机、麦克风、通讯录 | 运行时弹窗，用户可拒绝 |

**user_grant 三件套缺一不可**：`name` + `reason`（引用 string 资源）+ `usedScene`，漏了 reason 编译期就报错——这是合规的工程化兜底。

## 最小权限原则：从「删权限」开始设计

本应用是「零权限」的正面案例：

- 内容随包分发 → 不需要 INTERNET；
- 进度存本地 preferences → 不需要存储卡权限（应用沙箱内自由读写）；
- 无广告、无统计、无账号 → 不需要设备标识、剪贴板后台读取。

零权限的复利：

1. 隐私声明一句话：「不收集任何数据」；
2. 审核零权限风险点，通过率更高；
3. 用户信任成本低——权限列表空白就是最好的承诺。

**每加一个权限前先问**：有没有不申请权限的实现？数据能不能不采？能不能用系统 picker（用户主动选文件，无需存储权限）替代？

## 隐私声明的写法

上架隐私声明要与实际行为**逐条对得上**：

| 应用行为 | 声明义务 |
|---|---|
| 零联网 | 可声明「无网络访问」 |
| 本地偏好存储 | 声明「设置数据仅存于设备本地」 |
| 接入统计 SDK | 必须披露采集项、用途、第三方名称 |
| 申请 user_grant | 每项写明申请时机与用途 |

**审核常见驳回**：声明说「不上传数据」但代码里连了埋点域名；声明没提统计 SDK；reason 写「应用需要」这种空洞文案。

## 权限申请的运行时姿势（需要时）

```typescript
import { abilityAccessCtrl } from '@kit.AbilityKit';

const ctx: Context = getContext(this);
const atm: abilityAccessCtrl.AtManager = abilityAccessCtrl.createAtManager();
const result: PermissionRequestResult =
  await atm.requestPermissionsFromUser(ctx, ['ohos.permission.LOCATION']);

if (result.authResults[0] === 0) {      // 0 = 授权成功
  this.startLocate();
} else {
  this.showFallback();                   // 拒绝后的降级路径，不能是死胡同
}
```

拒绝后的体验：功能降级（手填位置替代定位）+ 引导（「设置里可开启」），**绝不反复弹窗骚扰**。

## 一句话总结

**权限是负债，能不申请就不申请**——零权限是设计出来的，不是删出来的；要申请的每一条，都配得上用户一句「为什么」的诚实回答。
