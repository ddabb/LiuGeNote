# 应用签名与证书体系：从 p12 到上架

未签名的 HAP 装不到真机上，签错的 HAP 过不了上架审核。签名不是流程配角，是发布链路的关键路径。

## 签名三件套

| 文件 | 角色 | 类比 |
|---|---|---|
| `.p12` | 开发者/企业私钥库（带密码） | 你的私章 |
| `.cer` | 数字证书（证书请求 CSR 签发） | 公开的身份证明 |
| `.p7b` | Provisioning Profile（含包名、设备、能力声明） | 「准许证」：谁能装、装什么 |

三者写进 `build-profile.json5` 的 `signingConfigs`：

```json5
"signingConfigs": [{
  "name": "release",
  "material": {
    "certpath": "sign/xingzhi-release.cer",
    "storePassword": "******",
    "keyAlias": "xingzhi",
    "keyPassword": "******",
    "profile": "sign/xingzhi-releaseProfile.p7b",
    "signAlg": "SHA256withECDSA",
    "storeFile": "sign/xingzhi-release.p12"
  }
}]
```

## debug 与 release 签名

| | debug | release |
|---|---|---|
| 用途 | 真机调试 | 上架/正式分发 |
| 证书来源 | DevEco 自动生成 | AGC 申请或本地生成后上传 |
| Profile 设备限制 | 调试设备列表 | 无设备限制（商店分发） |
| 可调试性 | 可 | 不可 |

**自动签名**（DevEco「Sign In」一键配置）只适合 debug——上架必须用 AGC 关联的正式证书手动配置 release。

## 手动配置 release 步骤

1. AGC「证书、APP ID 与 Profile」：创建证书（csr 签发 `.cer`）与 Profile（绑定包名 + 证书，选「发布」类型）；
2. 本地生成 `.p12`：Key Store 带密码（Keytool 或 DevEco 向导）；
3. 三件套下载入工程 `signingConfigs`，`buildOption` 里产品挂 release 配置；
4. `devecocli build`（release）产出 `*-signed.hap`，hdc 验证安装。

## 常见报错速查

| 报错 | 原因 | 处理 |
|---|---|---|
| `ERR_INSTALL_FAILED_SIGNATURE` | 签名与已装版本不一致 | 先卸载旧版，或统一签名 |
| `error: failed to get material` | build-profile 签名配置缺失/路径错 | 检查文件路径与密码 |
| Profile 过期 | `.p7b` 有效期到 | AGC 重新签发 Profile |
| 包名不匹配 | Profile 绑定的包名与 module.json5 不一致 | 改包名或重做 Profile |

## 安全纪律

1. **`.p12` 与密码绝不进版本库**——`.gitignore` 收好，私钥泄漏等于应用身份被盗；
2. 密码别硬编码在共享的配置模板里，本地文件或环境变量传入；
3. 团队协作：正式证书收拢在发布负责人手里，开发统一走 debug 自动签名；
4. 定期轮换：证书泄漏迹象或人员变动时重签发。

## 一句话总结

**p12 是身份、cer 是证明、p7b 是准许证**——三件套配齐 release，密钥看好不上库，签名链路就通了。
