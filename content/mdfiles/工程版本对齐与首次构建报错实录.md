# 工程版本对齐：hvigor modelVersion 迁移与首个构建报错清单

本文是脚手架搭建过程的**实录**：首次执行 `build_project` 连续撞上四个配置与 API 错误，逐个修复后方才出包。

## 报错一：Unsupported modelVersion of Hvigor 26.0.0

### 现象

```
hvigor ERROR: 00303028 Configuration Error
Unsupported modelVersion of Hvigor 26.0.0.
The supported Hvigor modelVersion is 6.1.1 ... less than or equal to
the preset version number 6.1.1 of DevEco Studio.
```

### 根因

工程模板按更高版本的 DevEco 生成，`hvigor/hvigor-config.json5` 里
`modelVersion: "26.0.0"`；而本机 DevEco Studio 内置 hvigor 的 modelVersion 上限是
**6.1.1**。构建链路第一关就校验这个版本号，直接拒绝。

### 修复

```json
// hvigor/hvigor-config.json5
{ "modelVersion": "6.1.1" }
```

## 报错二：两处 modelVersion 不一致

```
The modelVersion in hvigor-config.json5 is 6.1.1,
and the modelVersion in oh-package.json5 is 26.0.0
```

modelVersion 在 `hvigor-config.json5` 与根目录 `oh-package.json5` **两处声明、必须一致**。
只改一处会被一致性校验拦下。修复：

```json
// oh-package.json5
{ "modelVersion": "6.1.1" }
```

## 报错三：targetSdkVersion 格式要求

```
When API level is 10 or later, the value of
compileSdkVersion/compatibleSdkVersion/targetSdkVersion must be string,
Example: '5.0.0(12)'.
```

模板里的 `targetSdkVersion: "26.0.0"` 是新版本号格式，本机工具链要求
**`主版本.次版本.修订(API级别)`** 的括号格式。与 compatibleSdkVersion 对齐为：

```json
// build-profile.json5
{
  "targetSdkVersion": "6.0.0(20)",
  "compatibleSdkVersion": "6.0.0(20)"
}
```

> 经验：工程在团队成员间流转时，**工具链版本差**是脚手架最常见的一类首次构建失败。
> 建议把三处版本（hvigor-config / oh-package / build-profile）写进 docs，环境对齐从文档开始。

## 报错四：ArkTS 编译期 API 纠错清单

配置过了，编译期 `arkts_check` 又拦下 4 个真实代码错误，全部是 API 使用想当然：

| 错误 | 想当然写法 | 纠错 |
|---|---|---|
| `getRawFileContent` 返回 Promise | `const buf: Uint8Array = getRawFileContent(p)` | 本 SDK 该方法为异步签名，同步读取要用 `getRawFileContentSync(p)` |
| `Alignment.CenterStart` 不存在 | `.align(Alignment.CenterStart)` | `Alignment` 只有 `TopStart/Start/Center/End/BottomEnd` 等 9 个成员，横向滚动起始对齐用 `Alignment.Start` |
| BorderOptions 分边写法 | `.border({ left: { width: 3, color: c } })` | 正确形状是 `.border({ width: { left: 3 }, color: { left: c } })` —— width 与 color 各自是分边对象 |

### 教训

1. **静态检查先行**：`arkts_check` 在写完文件后立刻跑，四个错误 30 秒内全部暴露；
   如果攒到最后全量构建再排，定位成本翻倍。
2. **不要凭记忆写 API 形状**：`BorderOptions` 这类参数对象，成员结构记错就是编译错误，
   查定义比猜快。
3. **异步/同步双签名要分清**：`getXxx` 与 `getXxxSync` 返回类型完全不同，
   类型注解（`const buf: Uint8Array`）能在编译期立刻暴露误用 —— 这也是坚持给变量写类型注解的直接收益。

## 修复后

```
hvigor Finished :entry:default@CompileArkTS ... after 5s
hvigor BUILD SUCCESSFUL in 12s
```

首个 HAP 出包。整个过程没写一行新功能代码 —— **让构建链路先绿，是所有后续工作的前提**。
