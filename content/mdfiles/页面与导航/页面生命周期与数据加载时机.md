# 页面生命周期与数据加载时机：aboutToAppear 不是万能的

「数据在哪里加载」看似小事，放错时机会变成：白屏久、每次返回都重新加载、页面销毁后还在写状态。

## 两套生命周期，别混

**组件生命周期**（@Component / @ComponentV2 通用）：

```
aboutToAppear()   组件创建后、build 前（一次）
build()           首次渲染
aboutToDisappear() 组件销毁前（一次）
```

**页面生命周期**（@Entry 页面 / NavDestination 专属）：

```
onPageShow()      页面每次可见（含从后台/其他页返回）
onPageHide()      页面每次不可见
onBackPress()     返回键拦截
```

NavDestination 版本：`onReady`（就绪，拿参数）→ `onShown` / `onHidden`（显隐）→ `onBackPressed`。

## 时序图

```
首次进入：
  aboutToAppear → build → onPageShow → (可见)

跳转到下级页：
  onPageHide → (下级页活动) → 返回 → onPageShow
  ⚠ 本页 aboutToAppear 不会再次触发！组件还活着

销毁（路由出栈）：
  onPageHide → aboutToDisappear
```

## 数据加载时机速查

| 场景 | 正确时机 |
|---|---|
| 首次加载静态数据 | `aboutToAppear` |
| 每次返回都要刷新（列表回来看最新状态） | `onPageShow` / `onShown` |
| 需要路由参数 | NavDestination 的 `onReady`（aboutToAppear 时参数未就绪） |
| 动画/计时器启动 | `onPageShow`（可见才启动） |
| 停止计时器/保存进度 | `onPageHide` / `aboutToDisappear` |

**核心区别**：`aboutToAppear` 只跑一次，`onPageShow` 每次可见都跑。「返回列表页要刷新」写在 aboutToAppear 里，永远不生效——组件早建好了。

## 每次都加载还是缓存？

```
数据新鲜度要求高（答题状态、统计） → onPageShow 里刷新
数据不可变（文章正文、分类目录） → aboutToAppear 加载一次，缓存复用
```

避免的反模式：`onPageShow` 里无脑全量重载——返回一次闪一次加载态，用户会烦。

## 清理责任清单

`aboutToDisappear` 是**唯一可靠的清理点**：

1. 停掉计时器（`clearInterval`）；
2. 取消未完成异步的副作用（置 `alive = false`）；
3. 保存未持久化的状态（阅读进度兜底落盘）；
4. 注销全局监听。

忘记清理的症状很隐蔽：页面关了日志还在刷、后台计时器耗电、异步回来给已销毁组件写状态导致告警。

## 踩坑记录

1. `aboutToAppear` 里 `this.getUIContext()` 弹窗 → UI 未挂载不显示，挪 `onPageShow` 或用户事件里；
2. V2 组件里 `aboutToDisappear` 写成了 `private` → 编译报错（生命周期钩子不能 private）；
3. 异步回来直接写状态没判存活 → 数据到了页面没了，轻则无效重则异常；
4. 在 `build()` 里加载数据 → build 只做渲染，加载逻辑进生命周期或事件回调。

## 一句话总结

**一次的事进 aboutToAppear，每次可见的事进 onPageShow，收尾的事进 aboutToDisappear**——三个钩子各司其职，时机就是体验。
